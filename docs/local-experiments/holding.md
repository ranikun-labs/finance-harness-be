# Local holding experiment

This is an opt-in local/test experiment, not a production API or a real filing provider. The controller exists only with profile `local` or `test` (and neither `prod` nor `production`) and `finance.local-holding.enabled=true`. `server.address` must explicitly be `127.0.0.1` or `::1`; startup fails otherwise. Set `finance.local-holding.directory` to an absolute, private, dedicated local directory. It must be writable by the process and support atomic moves. Data is one ticker per current identity, stored in a file named by a SHA-256 digest of the identity. It is not encrypted. The directory is trusted; operators must restrict OS access, back it up or remove it as appropriate. This single-process experiment does not provide multi-instance coordination or a production retention, deletion, recovery, or account lifecycle policy.

The current identity comes exclusively from `CurrentUserPort`; the request cannot select an owner. `PUT /finance/local-holding` replaces the ticker and repeated identical PUTs have the same result. `GET /finance/local-holding/filing` returns a fixture for the saved ticker with a source, fixture timestamp and fictional period; it is not an official filing. Tickers are uppercase ASCII and must match `^[A-Z][A-Z0-9.-]{0,9}$`. No provider is contacted.

For a disposable HTTP harness without the normal database, use `localHoldingHarness` from test sources, set `HOLDING_TEST_OWNER` before startup, and supply `--server.port`, `--finance.local-holding.directory`, and `--management.endpoint.health.validate-group-membership=false`. Its identity is fixed at startup. This harness does not test shared identity or a production runtime. Point the FE dev-only proxy to the harness and enable both `VITE_LOCAL_GENERAL_ANALYSIS=true` and `VITE_LOCAL_HOLDING=true`. Never expose the harness to untrusted networks.
